# PC-monitoring UI redesign

Presentation-only redesign of the existing Streamlit application. The reference image was used for visual direction (deep navy, cyan/teal accents, compact hardware-style cards, health panel); every element was mapped to data the collector actually provides, and anything unsupported was left out.

## What did not change

Native C17 collector, Win32 monitor, SQLite WAL schema, `ipc.py`, `data.py`, `analytics.py`, `windows.py`, `child.py`, all four pages, the Alerts / Settings / Collector Health / Exit dialogs, their callbacks, queries, request IDs and button labels. Streamlit remains the UI framework; Plotly remains the only chart library; no external fonts, scripts or assets were added.

## Design element → data source

| Reference element | In the redesign | Real source |
|---|---|---|
| Collector Running pill, last sample | Header pills on every page | controller `status`: `collector.state`, `live.sampled_at_us`, `collector.last_commit_us` |
| "This Computer" strip | Logical processors, physical memory, system-drive size and free space | monitor `logical_processors`, `memory_total_bytes`, `memory_used_bytes`, `cpu_topology_supported`; drive from `shutil.disk_usage` (live OS reading) |
| CPU Usage card + gauge | Metric + ring; delta labelled "vs 30 min mean" | `live.system.cpu_percent`; observation-weighted mean of stored `cpu.percent` windows |
| Memory card + bar | Metric + bar + percent of total | `memory_used_bytes`, `memory_total_bytes`, `memory_percent` |
| Disk (C:) card + bar | Used GiB, bar, "live reading, not stored" | **Exception:** `shutil.disk_usage` on the system drive, read at render time. It is not a collector metric, is never written to SQLite and has no history. |
| Network card | Shows "Not collected" | The collector has no network metric; no throughput number is displayed |
| CPU / Memory charts | Area-under-line charts, same queries | stored `cpu.percent`, `memory.used` windows |
| PC Health & Insights | Check list | `write_healthy`, `age_seconds`, `pending_batches`, `backpressure`, `clock_warning`, `rejected`, `monitor_error`, open alerts |
| Top Processes | Top *tracked* processes with CPU bar | `live.top` (tracked only, as before) |
| Recent Alerts | Same list with status dots | `alert_events` / `alert_rules` |
| Performance Time Machine card | Entry card with real counts and button | `COUNT(*)` of windows, last commit |
| Alerts badge | Count badge on the Alerts button | `COUNT(*)` of open `alert_events` |

## Reference elements deliberately not built

Disk activity and network traffic charts, network throughput values, CPU model / "8 cores 16 threads", SSD capacity, OS edition, "6 new processes discovered in the last hour", the laptop and Windows artwork, per-process application logos and the version pill. The collector does not measure or report these; adding them would require new native metrics (out of scope) or invented values.

## Icons, naming and layout

- Of the 20 supplied neon icons, thirteen are used, as small WebP files in `python/pulsemetrics/ui/assets/icons/` (generated by `scripts/prepare_icons.py`, inlined as base64 data URIs, so no network requests and no new dependency): one per sidebar navigation entry and control button (eight), the four metric-card icons and the "This Computer" monitor icon. A missing file simply omits that icon. Each entry has exactly one icon: the second (Material) icon that `st.Page(icon=...)` added to every navigation entry was removed, along with the CPU/RAM/disk icons repeated in the "This Computer" strip, the panel-header icons, the sidebar footer card and the arrow on "Open Time Machine". `prepare_icons.py` still generates all 20 files; the other seven are not referenced.
- Sidebar navigation is custom: the native Streamlit navigation is hidden (`st.navigation(position="hidden")`) and replaced by `st.page_link` items so each entry carries its icon and an active highlight. Labels wrap instead of truncating, and the sidebar has a minimum width on desktop. The Alerts, Settings, Collector Health and Exit buttons keep their exact labels and callbacks; the Alerts button shows the open-alert count as a badge. Top-level column rows reflow to two columns below 1100 px and one column below 700 px. The Streamlit toolbar is minimal (`--client.toolbarMode=minimal`), so the Deploy button and developer menu are not shown.
- "V2" was removed from the interface (sidebar brand, version caption). The product name in the UI is "PulseMetrics". Internal paths such as the data directory name are unchanged for compatibility.
- Overview grid: header, "This Computer" strip, four equal metric cards (CPU, Memory, Disk, Network), a 4:4:3 row (CPU chart, Memory chart, health), and a 13:11:9 row (processes, alerts, Time Machine). Each row uses a fixed container height so panels line up. Disk and network time-series charts are not drawn because nothing is stored for them. "Processes discovered" and "Actively tracked" moved into the Top Tracked Processes header.

## Data-integrity rules kept

Unavailable readings display "Unavailable" (never 0); charts break at missing sequence intervals (`None` + `connectgaps=False`, linear segments, no smoothing); timestamps stay UTC; resource gauges are always neutral cyan — orange/red are used only for open alerts, collector faults and warnings that the collector itself reports (no invented CPU/RAM thresholds).

## Files changed

`.streamlit/config.toml`, `python/pulsemetrics/controller.py` (theme colour flags and the minimal-toolbar flag only), `python/pulsemetrics/ui/app.py`, `components.py`, `pages.py`, new `ui/theme.py`, new `ui/assets/icons/*.webp`, new `scripts/prepare_icons.py`, new `tests/ui_fixture.py`, `tests/test_ui_redesign.py`, and documentation (architecture, testing, user guide, course report, README, PROGRESS, screenshots README).

## Verification status and limits

See "UI redesign verification" in `testing.md`. In short: syntax, pure-Python tests and a logic harness were run without Streamlit/Windows; AppTest, Windows tests and browser rendering were **not** run and the redesign still needs the manual checklist and recaptured screenshots. The theme CSS targets Streamlit `data-testid` hooks of the pinned Streamlit 1.58; if a selector does not match, the page falls back to the native dark theme rather than failing.
