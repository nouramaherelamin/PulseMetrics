# User guide

1. Build and launch from README. The printed loopback URL works even if automatic browser opening is unavailable. Wait for the second native sample before expecting a CPU delta; the first is a warmup, not0%.
2. In **Overview**, cards show live monitor snapshots. Charts show committed collector windows and can lag live cards by a window plus normal processing. A readable database alone is not a live connection indicator. Open Collector Health to inspect heartbeat, last receipt/commit, accepted/rejected/dropped observations, write errors and bounded pending batches. The header pills show collector state and the live-sample and last-commit times; the *PC health & insights* panel lists only conditions the collector actually reports (write health, freshness, queue, clock warning, open alerts). The *This computer* strip shows the logical-processor count and physical memory the native monitor reports, plus the system drive's size and free space read live from Windows when the page renders. The Disk card is that same live reading; it is not stored and has no history. The Network card shows "Not collected" because the collector does not measure network throughput; hardware-model information is not shown.
3. In **Process Explorer**, search by name or PID and sort by CPU, memory, name or PID. Choose a process from the displayed page and Track. Identity includes exact creation FILETIME; a restarted same-name program is a different source. Untrack preserves history. Saved selections can be removed even when identity reads are unavailable. Ended tracked instances are shown separately. There is no process-kill control.
4. In **Performance Analytics**, choose a source and range. Counters show sums, gauges show last observed values and timers show mean measured milliseconds per window. Summaries weight averages by observation count. Counter rate divides by observed window durations, excluding missing windows. Chart zoom/hover uses actual UTC endpoints; selecting a point offers its Time Machine window. Memory insights compare real endpoints within one session and make no causal claim.
5. Run `pulse_sender.exe --port 8125` separately to demonstrate instrumented application observations. Choose `Measured metric sender` in Analytics. Its gauge is the number of its own in-flight checksum operations; its timer is QPC duration around real work. System/process CPU does not measure response latency.
6. In **Alerts**, choose a registered metric and an applicable field. `gt/ge/lt/le` are exposed with readable condition labels. A rule evaluates future committed observations. Multiple rules have independent IDs. Missing data does not recover an open alert. Disable a rule to close its open event with the explicit reason. Inspect its supporting window; if retention expired that window, the stored event evidence remains labelled as expired.
7. In **Performance Time Machine**, choose a UTC day/time range and a stored window from the timeline or selector. Previous/next follow session/sequence order. Health-only windows legitimately contain no metric rows. Compare only matching metrics within one session. Missing time or metric observations are not filled with zeroes. Queries disclose when only the latest500windows/2,000metric-window records are shown.
8. **Settings** saves sampling, window, refresh and retention bounds. Collection changes apply after Exit/relaunch; refresh applies on the settings rerun. To configure another instrumented source or ports, edit the runtime config before launch. Names/types/units must remain immutable for existing catalog entries.
9. Use **Exit PulseMetrics**, then wait for the clean or failed-drain outcome. The local server stops after the UI acknowledges it or a short deadline. Closing only a tab leaves the controller collecting. Reopen with the same data directory to retain history.

Use GiB/MiB for binary memory units; CPU values are percentages of whole-machine capacity. Exact UTC timestamps and session identity matter after clock adjustment. A Clock Warning keeps history truthful and pauses retention for the session. Do not interpret a stale chart as current activity or an unavailable measurement as zero.

Privacy: the database contains selected process display names, PID/creation identity and resource metrics. It does not contain command lines, environment variables or sampled private memory. Keep the runtime directory out of public repositories. For backup, stop cleanly and copy the whole runtime directory. The source package deliberately excludes all personal runtime history.
